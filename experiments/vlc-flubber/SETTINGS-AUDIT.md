# Planner settings versus Flubber VLC Player

Audit inputs: current main Experiment Planner recipe v5 (`test/fixtures/planner-recipe-v5.canonical.json`, main `3c6db83`), the P5 v2 contract (`docs/planner-p5-feedback-v2.md`), the separate Flubbercorder experiment reader, and the LibVLC player at `fd21f18`. This is a source and contract inventory, not playback qualification.

| Source | Settings | Current owner and VLC correspondence |
| --- | --- | --- |
| VLC preset `vlc-flubber-sidequest/v1` | `panelPercent`, `stepPercent` | Both are live player values. Panel height is 10–100% of video height; arrow step is 1–100% of each affect axis. |
| Flubbercorder experiment `flubbercorder-experiment/v1` | `video`, `panelPercent`, `stepPercent`, `requiredStreams` | Recorder binds the video and selected external stream requirements before a session. It passes panel and step to an armed player. The player's sampler fixes the video marker name and CSV destination at startup, so swapping video in the current process is not a settings update. `requiredStreams` controls Recorder subscriptions, not player output. |
| Planner P1–P3 | Study/workspace/video catalogue, questionnaires/languages/presentation, variants/ISIs/allocation/marker plan | These are authoring and Runner execution contracts, not settings in the standalone VLC side project. |
| Planner P4 | Target, viewport, calibration, units, reference, fit, feedback origin/offset/gap | Desktop layout uses a video/Flubber geometry contract. VLC's simple `panelPercent` does not express those positions or units. |
| Planner P5 input and response | Device and direction bindings; response mode, grid, duration, hold/repeat timing | VLC currently accepts arrow keys with one `stepPercent`. Planner P5 v2's `input.stepSize` is an **inactive compatibility field**; treating it as the active VLC arrow step would misapply the recipe. |
| Planner P5 appearance | Renderer selection, labels, eight colors, color anchors, halo, transparency, Flubber outline, Grid settings, visibility | VLC always paints its own native SVG Flubber with fixed color anchors/outline and has no Grid or procedural Face renderer. P5 also retains inactive compatibility fields (`flubberEnabled`, `gridEnabled`, `sizePercent`, `overlayPosition`, `lockPosition`). |
| Planner P5 animation | Six mappings: edge smoothness, oscillation frequency, projection amplitude, pulse synchrony, saturation, wave size variation | VLC's SVG currently uses hard-coded animation coefficients. There is no validated mapping from the full P5 contract to that renderer. |
| Planner P6 and policy | Optional XR profile; participant count, 1–240 Hz sampling, CSV/TSV output, authored LSL, complete-video playback/audio policy | The standalone Windows VLC player has no XR, uses fixed 30 Hz LSL/CSV and its own playback/marker contract. Runner owns actual session and XDF recording choices. |

The full Planner recipe is a strict, integrity-bound document. The Planner/Runner boundary requires complete versioned validation; picking a few fields from it and presenting the session as configured would be misleading. The minimum immediately compatible live import is the VLC v1 preset, with range and schema validation before either player value changes. A full Planner-to-VLC import needs a separately versioned interpretation plus real renderer, input, layout, sampling, and recording consumers, followed by the relevant gates.
