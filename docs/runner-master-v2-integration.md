# Runner master-v2 integration

RR-06/RR-10 consumes the explicit owner master-v2 contract. The supported native
reader validates original master bytes and reconstructs the selected P2/P3/P4/P5
content. Runner caches the already validated P4/P5 typed projections for execution;
it never rewrites a v2 document into v1 or repairs a source hash.

## Main composition seams

Register the owner modules `research_form_definition`,
`research_questionnaire_recipe_v2`, `research_planner_recipe_v2`, and
`research_planner_recipe_supported`, and the new Runner commands:

- `research_runner_master_start_v2`: request has exactly `version: 2`,
  `workspaceId`, `sourceText`, `participantId`, `selector`, `rerunConfirmed`,
  and `inputTestReceiptId`. No separate coded participant or demographics object.
- `research_runner_master_action_v2`: `runId` plus closed `action` with
  `type: presented | draft | submit | pause | resume | stop`. Presented carries
  `position`; Draft/Submit carry `position` and `answers: [{itemId,value}]`.
  Values have the exact tagged text/integer/singleChoice contract. Likert actions
  use singleChoice values with frozen option IDs. Native observation owns latency.
- The existing status, plan, rescan, preflight and history commands serve the
  explicitly supported source version. Existing v1 Start/actions retain their
  old ingress shape and cannot submit to a v2 attempt.

Main subsequently allocated supported `RunnerDocument` dispatch to Runner.
The production session module now uses P7's bounded canonical intake followed by
exact schema dispatch: supported master1/2 through S4, or unchanged PackageV1
through its owner. Unsupported or invalid sources never fall back to another
reader. Directory/history/recorder selection consumes the validated enum and
its exact policy. The participant number and exact source hash own output
identity; demographic answers never determine paths or allocation.

`renderMasterQuestionnaire(host,definition,presentation,answers)` returns the typed
form handle for a fields definition. Main must retain it for the occurrence and
destroy it when the occurrence changes. `read({allowPartial})` returns typed rows;
pass a map made from `[row.itemId,row.value]` to the master adapter's Draft/Submit.
Use the handle's disabled state while a submission is pending. Polling must not
replace active controls. Existing Likert rendering remains in the same dispatcher;
v2 status stores tagged singleChoice values and v1 status stores strings.

## Recorded semantics

Master-v2 plans use `master-sequence-v2`. Attempt, status, startup and response
envelopes are version 2. Startup2 contains exact master bytes and participantId,
and has no `legacyCodedParticipant`. Typed response rows retain exact values and
definition-derived choice labels; legacy Likert rows inside a response2 envelope
retain their original option/score/subscale members. Every displayed item is
mandatory for submission, including historical `required:false` metadata.
Incomplete drafts are retained as drafts and never advance the native sequence.

Plan/attempt/response/result files use their versioned names. Unchanged sample,
event, marker-profile and outcome records keep version 1. The information reader
dispatches through exact startup/source versions. A standalone profile reader
requires explicit `planVersion: 2` for a v2 plan; its historical default remains 1.
XDF finalization still requires actual stream footers. An observed protocol
completion is never substituted for durable recorder finalization.
