# Actual Planner core9 composition

Main shared integration, Backend Verification for CLI P1–P7 seams. The app
registers nine closed consequential operations over its existing owner editors.
`planner-core9-composition.js` only dispatches those owners and the fixed native
effect adapter; it contains no editor, compiler or filesystem authority.

Native boot connects effects with an ordered revision barrier. Workspace/media
preparation commits bridge state first and actual P1 state second, then projects.
Changing workspace also uses the existing P3 reset through its prepared state
hook. Catalogue preparation validates complete entries before state publication;
restored declarations require exact fresh matching, never fabricated readiness.

P2 import requires a genuinely pristine allocated slot and retains exact source
bytes through save. Prepared save validates and allocates definitions/modules
before native storage; acknowledged receipt precedes synchronous editor/app
adoption. Existing language routing is reconciled without changing route choices.
The full P2 snapshot explicitly emits v2/hooks-v3 when it includes typed forms.

P3/P4/P6 confirmation uses actual future owner snapshots and the registry's
prepared-owner validation. P1/P2 use their current validated snapshots. P5 is
captured only during final Save. Final compilation uses the existing strict
version-specific master compiler. Open publishes the fixed ten steps, preserves
the immutable source only after completion, and does not restore permissions or
confirmation. Exact unchanged copy remains possible without media reauthorization.

Actual app tests found and corrected: redundant unchanged P2 sync invalidating
async preparations; aliased app arrays changed before guarded editor restoration;
new modules omitted from existing language routes; fresh CLI default slots losing
pristine import eligibility; and native workspace switching skipping GUI P3 reset.
Independent S3 review identified the latter plus GUI typed-file parity. The P3
reset is integrated; GUI supported-version file adapters remain separately owned
until collected and wired. No complete GUI/CLI parity claim is made here.

Evidence: uninstrumented headless Chrome, all nine handlers and actual owner
compilers/registry, 40 checks in
`D:/GitHub/.affect-checks/main-core9-allhandlers2-20260912/receipt.json`.
The fixture explicitly injects synthetic native receipts and geometry. It covers
legacy ordered Open, exact-byte copy, workspace/media publication, EN/DE typed
demographics saves, real P1/P2/P3/P4/P6 confirmation, final typed master save,
file/folder media intake, pristine questionnaire import and source save. It is
not evidence of disk persistence, decoding, native CLI execution, Runner or XDF.
Earlier failing receipts are retained; their test-only diagnostic instrumentation
was removed before the successful uninstrumented run.

Commands that publish a useful partial draft can return `incomplete` with
`result.published`/`updatedOwners` and explicit domain issues (media pending or
remaining unsaved language slots). This is not final recipe readiness. Async
dependency rebinding can reject a subsequent mutation as stale; clients must
query actual owner state and use a new request after it settles, never retry a
possibly completed effect blindly. Final Save must return its exact receipt.

Native-feature build, actual external mock, Runner qualification, physical ISI
timing and same-master XDF/viewport screenshot correspondence remain separate
required gates. No fallback or capability flag is changed by this composition.

The full Research Node suite ran 1,093 tests: 1,092 passed and one source-layout
assertion still expected the old inline workspace event handler. It was updated
to assert both the exact event delegation and the extracted shared projection;
no runtime expectation or native access allowlist was relaxed.
